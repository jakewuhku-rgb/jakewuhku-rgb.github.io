Transport Layer: Exam Fast-Review Cheatsheet

Comprehensive high-density summary of protocols, architectures, formulas, and state models.

1. Transport Core & Demultiplexing

  • Role: Logical end-to-end communication between processes (Network layer handles host-to-host).
  • UDP Demux (2-Tuple): (Destination IP, Destination Port). Packets with different source IPs/ports matching this 2-tuple enter the exact same socket.
  • TCP Demux (4-Tuple): (Source IP, Source Port, Dest IP, Dest Port). Server listens on welcoming socket, then spawns a dedicated socket per client 4-tuple.
  • Stack Protocol Identifiers:
    • Ethernet Frame Type → IP
    • IP Header Protocol ID: 6 (TCP), 17 (UDP), 33 (DCCP), 132 (SCTP)
    • Transport Header → Port Number

2. UDP vs. TCP Quick Comparison

Feature UDP (RFC 768) TCP (RFC 793, 9293)
Connection Connectionless (0 RTT) 3-Way Handshake (1 RTT)
Reliability Unreliable, unordered Reliable, strictly ordered byte-stream
Header Size Fixed 8 bytes 20 – 60 bytes (Options field)
Flow / Congestion None (rate uncontrolled) Flow control (rwnd) & Congestion (cwnd)
Typical Use DNS, VoIP, Streaming, QUIC Web (HTTP/1.1, HTTP/2), Email, SSH, FTP
  • UDP Header Fields (8B): Source Port (16b), Dest Port (16b), Length (16b), Checksum (16b).
  • Internet Checksum: 1's complement sum of 16-bit integers across header, payload & IP pseudo-header. Receiver sums all words + checksum; must equal all 1s (0xFFFF).

3. Reliable Data Transfer (RDT) & Pipelining

Stop-and-Wait Sender Utilization: $$U_{\text{sender}} = \frac{L / R}{RTT + (L / R)}$$
Pipelined Protocol Utilization ($N$ packets in flight): $$U_{\text{sender}} = \frac{N \cdot (L / R)}{RTT + (L / R)}$$
Mechanism Go-Back-N (GBN) Selective Repeat (SR)
ACK Scheme Cumulative ACK up to $n$ Individual ACK for each packet
Sender Timers 1 single timer for oldest unACKed packet Individual timer per packet
Timeout Action Retransmits entire window from send_base Retransmits only the timed-out packet
Receiver Buffer Discards out-of-order packets; re-ACKs highest in-order Buffers out-of-order packets

4. TCP Segment, MSS/MTU & RTT Estimator

  • Seq Number: Byte-stream position of the 1st byte in segment.
  • ACK Number: Next byte expected from sender (cumulative).
  • MSS & MTU: $\text{MSS} = \text{MTU} - (\text{IP Header} + \text{TCP Header})$. Default Min MTU = $576\text{ B} \rightarrow \text{MSS} = 536\text{ B}$. Ethernet MTU = $1500\text{ B} \rightarrow \text{MSS} = 1460\text{ B}$.
Estimated RTT (EWMA with $\alpha = 0.125$): $$\text{EstimatedRTT} = (1 - \alpha) \cdot \text{EstimatedRTT} + \alpha \cdot \text{SampleRTT}$$
Deviation RTT (Safety Margin with $\beta = 0.25$): $$\text{DevRTT} = (1 - \beta) \cdot \text{DevRTT} + \beta \cdot |\text{SampleRTT} - \text{EstimatedRTT}|$$
Timeout Interval Calculation: $$\text{TimeoutInterval} = \text{EstimatedRTT} + 4 \cdot \text{DevRTT}$$ *Note: Retransmitted segments are ignored when sampling RTT (Karn's algorithm to eliminate ACK Ambiguity).*

5. Flow Control & Connection Lifecycle

  • Flow Control: Protects receiver's socket buffer from overflowing. $$\text{LastByteSent} - \text{LastByteAcked} \le \text{rwnd}$$ $$\text{rwnd} = \text{RcvBuffer} - [\text{LastByteRcvd} - \text{LastByteRead}]$$
  • TCP 3-Way Handshake (Setup):
    1. Client → Server: SYN = 1, Seq = $x$
    2. Server → Client: SYN = 1, ACK = 1, Seq = $y$, Ack = $x + 1$
    3. Client → Server: ACK = 1, Seq = $x + 1$, Ack = $y + 1$ (can piggyback data)
  • TCP 4-Way Teardown & TIME_WAIT:
    • Client → Server: FIN=1 → Server returns ACK (Client enters FIN_WAIT_2).
    • Server → Client: FIN=1 → Client returns ACK (Client enters TIME_WAIT).
    • Why TIME_WAIT = $2 \times \text{MSL}$? Guarantees server receives final ACK (retransmits ACK if lost) and lets old duplicate segments die out in network.

6. TCP Congestion Control (Tahoe, Reno, CUBIC)

Effective Sending Rate Limit: $$\text{Rate} \approx \frac{\text{cwnd}}{\text{RTT}} \text{ bytes/sec}, \quad \text{In-Flight} \le \min(\text{cwnd}, \text{rwnd})$$
  • Slow Start (SS): Starts at $\text{cwnd} = 1\text{ MSS}$. Grows exponentially (doubles every RTT, $+1\text{ MSS}$ per received ACK) until $\text{cwnd} \ge \text{ssthresh}$.
  • Congestion Avoidance (CA): Linear growth ($\text{cwnd} = \text{cwnd} + 1\text{ MSS}$ per RTT).
  • Fast Retransmit: 3 Duplicate ACKs (4 identical ACKs total) triggers immediate retransmission without waiting for timer timeout.
  • Loss Event Handling:
    • Timeout: Set $\text{ssthresh} = \text{cwnd} / 2$, drop $\text{cwnd} = 1\text{ MSS}$, enter Slow Start.
    • 3 Duplicate ACKs (Tahoe): Drops to $\text{cwnd} = 1\text{ MSS}$ (Slow Start).
    • 3 Duplicate ACKs (Reno): Sets $\text{ssthresh} = \text{cwnd} / 2$, $\text{cwnd} = \text{ssthresh} + 3\text{ MSS}$ (window inflation, Fast Recovery). On fresh ACK → sets $\text{cwnd} = \text{ssthresh}$ → enters CA.
  • Modern Variants:
    • TCP CUBIC: Uses cubic function centered at time $K$ where window reaches $W_{\max}$. Quick initial ramp-up, flattens near capacity, then explores aggressively. Default in Linux.
    • Delay-Based (BBR): Keeps pipe full without buffering or causing bufferbloat by comparing measured throughput with uncongested throughput (${\text{cwnd}}/{\text{RTT}_{\min}}$).

7. Modern Evolution: QUIC & HTTP/3

Middlebox Problem

SCTP & DCCP failed wide deployment because middleboxes/firewalls drop unknown L4 protocol IDs. QUIC builds on UDP in user space, rendering it transparent to network middleboxes.

0/1-RTT Handshake

Standard TCP+TLS requires 2 to 3 serial round-trips before data can flow. QUIC merges connection state, loss recovery, and TLS 1.3 crypto parameters into a single 1-RTT (or 0-RTT for resumed connections) handshake.

No Head-of-Line (HoL) Blocking

In HTTP/2 over TCP, a single lost packet halts delivery across all multiplexed streams. QUIC isolates stream recovery at L4: packet loss in Stream A only delays Stream A, while Streams B and C continue uninterrupted.
